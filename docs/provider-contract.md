# Provider contract

A *provider* is a self-contained Terraform root configuration under
`terraform/providers/<name>/` that provisions one Linux server and registers
it in the Ansible dynamic inventory. Providers are interchangeable: the
Makefile, the Ansible playbook and CI never special-case a provider. That
only works because every provider fulfils the contract below.

The easiest way to comply is to start from
[`terraform/providers/_template/`](../terraform/providers/_template/) — it
already satisfies every rule. See [CONTRIBUTING.md](../CONTRIBUTING.md) for
the step-by-step guide.

## Required files

| File | Purpose |
|------|---------|
| `terraform.tf` | `required_version = ">= 1.6"` + pinned providers (`~>` constraints) |
| `providers.tf` | provider configuration (credentials wired from variables) |
| `main.tf` | server resource(s) + `module "ansible_inventory"` call |
| `variables.tf` | credentials + provider-specific vars + the standard connection vars (alphabetical) |
| `outputs.tf` | the contract outputs |
| `inventory.yml` | dynamic inventory pointing at this directory |
| `terraform.tfvars.example` | every variable, commented, with its default |
| `README.md` | prerequisites (account, token, SSH key) and usage |
| `tests/*.tftest.hcl` | credential-free tests (mock the cloud provider; see the digitalocean tests) |

## Rules

### 1. Contract outputs

Every provider MUST expose exactly these output names:

```hcl
output "server_ipv4" {
  description = "Public IPv4 address of the Palworld server."
  value       = <your server resource>.ipv4_address
}

output "server_name" {
  description = "Human-readable name of the server instance."
  value       = <your server resource>.name
}
```

`make output` and `make forget-host` rely on them.

### 2. Ansible inventory module

Every provider MUST instantiate the shared module **exactly once**:

```hcl
module "ansible_inventory" {
  source = "../../modules/ansible-inventory"

  host_ip         = <your server resource's public IPv4>
  ansible_user    = var.ansible_user
  ansible_ssh_key = var.ansible_ssh_key
  ansible_python  = var.ansible_python
}
```

The module owns the `ansible_host` resource, the inventory group name
(`palworld` — what `ansible/playbook.yml` targets) and the connection
variable names. Never create an `ansible_host` resource directly.

### 3. Standard connection variables

Declare these three variables with exactly these names and defaults (copy
them from the template):

| Variable | Default | Meaning |
|----------|---------|---------|
| `ansible_user` | `"root"` | remote user Ansible connects as |
| `ansible_ssh_key` | `"~/.ssh/id_ed25519"` | private key path on the control machine |
| `ansible_python` | `"/usr/bin/python3"` | remote Python interpreter |

### 4. Inventory file

Ship an `inventory.yml` next to the Terraform code:

```yaml
---
plugin: cloud.terraform.terraform_provider
project_path: terraform/providers/<name>
```

`project_path` is resolved relative to the working directory, which is why
all commands run from the repository root (the Makefile guarantees this).

### 5. Credentials

- Every credential is a variable with `sensitive = true`, **no default**, and
  a `validation` block rejecting empty values (clear error beats a cryptic
  401 from the cloud API).
- Document the `TF_VAR_<name>` environment variable in the provider README.
- Never write credentials into committed files; `*.tfvars` is git-ignored.

### 6. Version pinning

Pin providers in `terraform.tf` (`required_version = ">= 1.6"`, `~>`
constraints), and commit the `.terraform.lock.hcl` generated by your first
`terraform init`.

### 7. Supported images

The default OS image MUST be one the Ansible roles support: currently
Debian 13 (trixie) or Ubuntu 22.04/24.04/26.04. Document the valid image
names/slugs in `variables.tf` and the README.

## Remote state

State is local by default (simple, single-player-friendly): it lives in the
provider directory and is git-ignored. For teams, configure a remote backend
in the provider directory, e.g.:

```hcl
terraform {
  backend "s3" {
    bucket = "my-terraform-state"
    key    = "palworld/digitalocean.tfstate"
    region = "eu-west-1"
  }
}
```

Note that the `cloud.terraform.terraform_provider` inventory plugin reads the
state through `terraform show`, so remote backends keep working as long as
`terraform` can authenticate from your machine.
